# Sorszámvadász

**Version:** 1.0  
**Status:** Living document

---

# Vision

Sorszámvadász exists to help a small community coordinate limited "sorszámok"
during the Ördögkatlan Festival as simply, quickly and reliably as possible.

The application is intentionally focused on one problem.

It is **not** a ticketing system.

It is **not** an event management platform.

It is a coordination tool.

---

# Target Users

- Festival participants
- Volunteers ("Sorszámvadászok")
- Organizers / Administrators

Approximately 30–40 users.

---

# Design Principles

## Simplicity

Every screen should answer exactly one question.

Examples:

- What do I want?
- What should I request?
- What is today's status?

If a feature complicates the participant experience,
it does not belong in Version 1.

---

## Mobile First

The application is designed primarily for mobile phones.

Desktop support is secondary.

---

## Reliability

Reliability is preferred over visual effects.

No unnecessary animations.

No unnecessary dialogs.

No distracting UI elements.

---

## Hungarian First

The entire user interface is Hungarian.

Source code remains English.

---

## Community First

The application exists to help the community.

Every feature should reduce confusion or save time.

---

# Success Criteria

The project is successful if:

- participants can submit requests without explanation
- volunteers know what to request
- administrators can manage one festival day in seconds
- the morning queue becomes less chaotic

---

# Version 1 Goals

Participant:

- Remember name
- Browse programmes
- Select
  - Szeretném
  - Ha marad

Volunteer:

- Request up to two performances
- Maximum four sorszám per performance

Administrator:

- Import programme list
- Close requests
- Re-open requests
- Reset one day
- Demo mode
- Live mode

---

# Things We Explicitly Do NOT Build

Version 1 intentionally excludes:

- payment
- user accounts
- Facebook login
- Google login
- notifications
- chat
- analytics
- advertisements

---

# Guiding Question

Whenever we consider a new feature we ask:

> Does this make the festival morning easier?

If the answer is "no",
the feature goes into the backlog.

---

# Motto

Simple.

Reliable.

Community first.
